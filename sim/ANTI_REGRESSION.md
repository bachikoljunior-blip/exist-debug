# 再発防止ゲート(最優先・毎サイクル照合)

目的: アシスタントが「verify / defer / 理解した気」パターンに戻らないための構造ゲート。
これは願望メモではない。**結論を出す前に必ず下の5点を照合する検問**。1つでも当てはまったら、その結論は再発。破棄して逆をやる。

## 再発シグネチャ(これが出たら戻ってる)
1. 「既に十分 / 変更不要 / 経済は既に体現してる」— 判断を避けている。→ 決めて作る。
2. 「Go待ち / ユーザー判断待ち」を、任された範囲で言う — 丸投げ。→ 自分で決める。
3. 承認・些末を質問で返す — offload。→ 自分で決めて進む。
4. 「わかった / 理解した / 伝わった」と理解を主張・演じる — 成果でなく言葉で示そうとしている。→ 言わない。理解は作ったもので示す。
5. ユーザーの口調を真似る/口調を作る — 気持ち悪い。→ 素の平易な言葉。断定の演出をしない。
6. **判断をリポジトリに「要ユーザー判断」として置く** — 2の変形で、口では言わないぶん見逃しやすい最悪形。
   OPEN項目・コード内コメント・報告の末尾に「3択を提示」「方針決定を待つ」「勝手に選ばない」と書いた瞬間に再発。
   → その場で決めて実行し、決定と根拠をログに書く。リスクは sim先行 + 平均保存 + revert可(+バッテリー)で管理する。
   **例外は「不可逆で取り返しがつかない」「明らかに任務外」だけ**。経済変更は例外ではない(手順があるから自分で回せる)。
   **機械の検問(2026-07-26 実装=これが本体。以下の自己点検は補助)**: `sim/tools/decision_guard.sh`
   - **Stopフック**(repo `.claude/settings.json`)が毎ターン自動発火し、①リポジトリの生きた置き場 ②直近のアシスタント発言
     (「3択/どちらにしますか/指示をください/お待ちします」等の丸投げ表現+「理解しました」等の演技)を検査し、
     引っかかると exit 2 で手番へ差し戻す=言葉の反省でなく機械が止める。
   - **git pre-commit**(SessionStartで自動設置)が違反を履歴に入れない。
   - 実証済み(5ケース回帰): 本物の丸投げ3種(3択/承認待ち/理解の演技)=全て検知、健全2種(決定報告/仕組みの説明)=全て通過。
   - 検問自身の欠陥を2つ発見して修正: (i)禁止句の中の語で自己免罪(「方針決定を待つ」の『決定』でマーカー成立)→禁止句を除去した残りで判定 (ii)仕組みを説明する文が自分の禁止句列挙で落ちる→近傍にメタ語彙(検問/禁止句/検知等)があれば行為でなく言及として除外。
   自己点検(**生きた置き場だけを見る。履歴の書き換えは改竄なのでしない**):
   `grep -n "要ユーザー判断\|判断を待つ\|勝手に選ばない\|Go待ち" sim/BACKLOG.md sim/PERFECTION.md sim/FUN_audit_R35.md sim/SENSE_R35.md index.html sim/sim.js sim/runner.js sim/params.js`
   → ヒットは「決定済み+実行状況」か「これは過去の再発だったという注記」のどちらかであること。
   「待つ/選ばない/提示する」のまま残っていたら再発中=その場で決める。HANDOFF等の履歴ログは対象外(当時の事実として保存)。

7. **測定/判定を「動いているつもり」で通す** — 判定器を書き換えたのに、その判定器が実際に数字を受け取れているかを見ずに
   「検出力は保持」と結論する。4(理解の主張)の測定版で、緑/赤の見た目が出るぶん見逃しやすい。
   → 判定を変えたコミットでは、**その判定が実データを読んだ出力**(比の実数・件数)を必ず添える。0件/測定不能が出たら
   それは機構の死ではなく**まず自分の配線を疑う**。
   **機械の検問その2(2026-07-26 実装)**: `sim/tools/qa_ref_check.js` = QAツールが `getElementById('X')`/`#X`/
   `typeof F==='function'` で参照する名前が index.html に実在するかを静的検査(実在しない=その検査は無言で空振り)。
   同日に同型を3件検出: save_robust/fmt_extreme の `#cookieCount`・`#cps`、crit_felt の `critChance`、
   full_playthrough の `clearMonsters`。pre-commit で `sim/tools/*.js` か `index.html` を含むコミットに自動実行。
   回帰実証: 架空のid/関数名を仕込むと検知・戻すと合格。
   **機械の検問(2026-07-26 実装)**: `sim/tools/measure_wiring_check.js` = 判定器(runner.js の MECH)が読む
   カウンタ名を抽出し、sim.js の全周回記録リテラル(`sim.runs.push({...})` ×2 と `replayRun` の `return {...}`)に
   載っているかを静的検査。欠けたら exit 1。`sim/sim.js` か `sim/runner.js` を含むコミットで pre-commit が自動実行する
   (decision_guard.sh --install-git-hook が設置)。回帰実証: 1フィールドを落とすと検知・戻すと合格。

## 測定模型の罠(2026-07-26 に2回踏んだ・見つけ方も書く)
- **固定cpsのままの一発外挿**: 「今の毎秒で目標額に届くまでの秒数」を一度に足す模型は、貯める間の
  再投資(cps成長)を無視するので、序盤や転生直後の低cps局面で桁が跳ぶ。実例: pace_audit が「転生に
  1e61日」、実況ドライバの転生待ちが「7.4e11日」。どちらもプレイの良し悪しでなく模型の粗さが結果を支配。
  → 直し方は共通: **残りの5%だけ進める→買い物→cps再評価** の反復にする(刻み上限に当たったら打ち切りを明示)。
  → 見つけ方: 出てきた時間が人間の寿命や既知の実測(例: ステージ2到達=33日)と桁で合わなければ、
    ゲームの設計を疑う前に自分の模型を疑う。

## 明示列挙の腐り(2026-07-26 に同日3回踏んだ・機械で止めた)
機能を後から足すたびに「関係する明示列挙」を更新し忘れ、**足したものだけが黙って落ちる**。
目視レビューでは絶対に見つからない(コードは正しく見え、赤も出ない)。同日の3件:
1. **測定配線**: 判定器が読むカウンタが周回記録リテラルに無く、判定は常に0を受け取っていた(⑬が全NG)。
2. **凍結配線**: 停止中に期限をずらす列挙から4種(追い焼き・会心フィーバー・ゴールドラッシュ・注文の制限時間)が漏れ、
   手を出せない間にそれだけが溶けていた。
3. **永続配線**: 転生/やり直しの持ち越し列挙から漏れた state が永久消失していた(図鑑・解放ラッチ・やり直しの7項目)。
→ 対処は毎回同じ: **静的検問を1本作って pre-commit に配線する**(measure_wiring / freeze_wiring / persist_wiring)。
  「見つけたら直す」で終わらせない。次に同種の列挙を書いたら、その場で検問も書く。
→ **検問自身が同じ罠を踏む**: persist_wiring の初版は一覧を freshState の return だけから取り、
  codex/skills/eq2Owned/revealedEver を集められていなかった(=持ち越しを消しても「OK」と言った)。
  検問を書いたら必ず **わざと壊して名指しで落ちることを確認**し、一覧の取り方に自己検査(代表キーの存在確認)を入れる。

## 判定器を信じる前に判定器を測る(2026-07-26 に同じ日で5回踏んだ)
「動いているように見える判定器」は赤も緑も出すので目視では見つからない。実際に踏んだ5種:
1. **NaN汚染**: `state = {}` から測ると `Math.max(0, undefined)=NaN` が伝播して全件「動かない」。
   → `freshState()+ensureState()` で全キーを埋める。
2. **モジュール変数の残り**: `freshState()` は state しか戻さない。金ブースト・余熱・編成倍率は
   モジュール変数なので前の測定が漏れる。→ 明示的に消す。
3. **偽クロックの微小進み**: off と on の間に Date.now() が進み `runTempoRamp()` が 1e-7 揺れる。
   許容差 1e-9 だと誤検出、1e-6 に上げると小さな加算効果(毎秒+50)を見落とす。
   → **測定中は Date.now を固定する**。これで厳密比較が意味を持ち、実行ごとに結果が変わらなくなる
   (固定前は同一ビルドで死に札が 5件/2件/1件 と揺れた)。
4. **隔離したつもりで隔離できていない**: `const SKILLS = SKILL_NODES.map(...)` はコピーなので
   `SKILL_NODES` 側を書き換えても `skillEffect` には効かない。→ 実際に読まれる配列を書き換える。
5. **存在しない関数への三項フォールバック**: `typeof f === 'function' ? f() : 別の式` は f が無いとき
   黙って別の式になり、測っているつもりの面が消える。→ 書かない(qa_ref_check が検出する)。
判定器を作ったら必ず **①自己検査(効くと分かっているもので面が動くか) ②同一ビルドで2回以上走らせて
同じ結果か ③「動かない」と出た件は個別に絶対値で確認** の3つを通す。
「動かない」の分類も分けること: 相対で動く / 効くが小さい / 事象駆動・条件付き(静的観測の対象外) /
**説明できない0**。最後だけが欠陥の候補。
